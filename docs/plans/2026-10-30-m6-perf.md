## 二、机制裁定

1. **帧统计 `JUI_FRAME_STATS`**（对照 MyGO 的 `MYGO_FRAME_STATS`）：unset 不测；`1` 记录超过 8 ms 的帧；`all` 全记；数字为毫秒阈值。每帧一行 stderr：build（含遍数与轮数）、layout、paint、present 各段耗时、该帧分配字节（`ThreadMXBean` 每线程口径，JVM 与 native 都可用，同 AllocSpike）、GC 次数。分段点：`Engine.frame` 内部（build 各 pass、每轮 layout）与 `MacWindow` 的提交回调。测试只锚定阈值解析与分段累加（注入时钟/记录器）。
2. **外壳基准 `./build.sh shellbench`**（新）：`jui.spike.ShellBench` 直接用 `NotesDemo` 的视图（进程内、无窗口）：不变帧 1000 次 p50/p95/max（门槛 p95 < 4 ms）；不变帧分配（native，口径同 AllocSpike，门槛 ≤ 32 KB 含应用代码）；**打字延迟**：搜索框逐键 1000 次，每键 key→下一帧 paint 完成的时长，报 p95/max（门槛 ≤ 1000/120 ms，按 120 Hz 屏的"一帧"）；滚动 1000 帧（门槛 p95 < 4 ms、图集不满）。
3. **启动与内存 `./build.sh bench` 扩展**：`bench <runs> notes` 模式构建 `NotesDemo` native 并按原型的口径测 main()→应用就绪→窗口就绪→首帧提交→空闲 3 秒 physical footprint（复用 `idle_memory` 的 vmmap 口径）。NotesDemo 加 `--quit-after-first-frame`（首帧提交后打印时刻并退出，供启动测量；不改动正常交互）。门槛：< 200 ms、< 80 MB。
4. **布局缓存**（§7.4，对照 `layoutcache.go` 语义，按 j-ui 引擎适配）：
   - 布局前一遍 **sameLayout** 比对：节点的布局输入（尺寸/min/max/percent、grow/shrink/basis、padding/margin、对齐、gap、wrap、row/reverse、绝对定位 insets、clip、滚动旗标与**滚动偏移**、字体样式继承集、文本内容/Spans、placeOn）与上一帧相同，且子元素是同一批身份同序、每个递归相同 → 标记可复用。
   - **易变集**（永不复用，其子树也不保留）：列表（行按偏移边布局边建）、输入框（文本由编辑器布局）、placeOn 附加、modal/popover 面板（absolute 定位依赖外部盒子）、滚动偏移变化的容器。
   - 复用：布局时给同样的约束盒 → 直接取上一帧记录的盒子（w/h/x/y、contentW/H、子盒递归）；测量宽度（max/min content）与文本叶子排版也按参数复用（TextEngine 全局缓存之外的每元素持有，一代两个宽度）。
   - 文本系统换代（字体释放）时整体失效。Dev 开关 `-Djui.layoutCache=off` 供调试。
   - **等价测试**：随机树生成器，每帧随机改若干处，开/关缓存各布局一遍逐盒比对（MyGO `TestLayoutCacheMatches` 的做法）；516 既有测试全绿；listbench/areabench/shellbench 不回归并报告命中率。
5. **图集回收**：每个 entry 记 `usedFrame`（光栅化与绘制查找时戳）。到达上限不再增长时：按活跃（近期帧用过）重打包——新建图集只放活跃字形、坐标重排、generation+1 整图上传（复用计划四的增长机制），冷字形自然淘汰，再次用到时重光栅化。listbench 用小起始图集强制经历多次重打包仍通过；逐出后重画的字形像素一致。
6. **图谱视图 `GraphDemo`**（6.12 验收）：`./build.sh demo Graph`。一张静态分层布局的小图谱：节点（圆 + 文字标签）、边（线段）、悬停高亮（节点放大 + 邻边变色）、`animationFrame` 做一次入场动画。只用公开 Painter API。
