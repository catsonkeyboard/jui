## 二、Architecture

### 2.1 保留一个编辑模型，不增加第二套输入系统

- 保留 `Node.INPUT`；新增 `Node.multiline`，`TextEdit` 增加对应模式。`textInput` 和 `textArea` 共用同步、撤销、焦点、钩子和平台边界。
- 保留 `TextEdit(String)` 的单行构造，增加 `TextEdit(String, boolean multiline)`；创建多行编辑器时不能先经过单行清洗，否则首次传入的换行会丢失。
- `Engine.textInput(index, ref, multiline)` 为共同入口，旧入口委托 `false`。若同一身份从一种输入模式换成另一种，先同步旧模型的已提交编辑，再以当前 `TextRef` 重建新模式的编辑状态；旧组字丢弃并通知输入法，选区、滚动和撤销历史重置。切换不伪造一次文本 `changed()`。应用希望独立保留两种控件的编辑状态时应使用不同 key。
- `settleInputs()` 继续在构建完成后落实选项和显示文字；`password()` 对多行框无效（同 MyGO），其他计划一选项继续有效。

### 2.2 给缓存的排版结果加行表，不在查询时保留原生对象

- `TextEngine` 按硬换行分段，每段交给 Core Text 一起断成视觉行；每行存 UTF-16 起止下标、硬换行结束下标、top/height/baseline/width、字形起止位置。
- 软换行末尾的空格保留在本行，用于选区、命中和光标位置；不得只按剔除尾部空格后的宽度计算。
- 字素簇边界和各行的光标 x 在 cache miss 时计算；用 `CTLineGetOffsetForStringIndex` 求字素簇边界的位置，不以“下一个字形的 x”代替连字内的插入位置。
- 实测补充：每次编辑都重排未改变的硬段，会使5000字符场景超过4ms。最终复用同一有界缓存中的硬段结果，再合成整文数组；所有硬段仍即时测量，不估高、不虚拟布局。光标位置仍逐字素调用上述原生函数，放弃字形原点近似，并以连字/kerning逐点对照和段落复用测试守护。
- 原生 `CTLine`、typesetter 和 attributed string 在排版时释放；缓存只保留 Java 数组和已有的规范化字体引用。查询行、光标、选区不再下调 Core Text，也不分配逐行对象。
- 仍使用整个字符串的有界排版缓存。首版的编辑、字素边界计算和重新排版是线性成本，不宣称适合大文档；绘制只处理可见视觉行及上下各一行。
- 行表使“只有换行、几乎没有字形”的布局也占内存，因此不能只按 glyph 数量限制缓存。两代缓存各增加源 UTF-16 单位预算（200,000），与原有 entry/glyph 预算一起触发轮换；单个超预算布局允许占一代，重复读取仍命中，而不是每个不变帧都重新排版。加全空行布局的缓存轮换测试。

### 2.3 事件期间必须能取得最新布局

现有键盘事件立即改 `TextEdit`，几次事件之间不一定有一帧。只读上一帧的 `e.layout` 会让“插入换行后马上按 ↑”按旧行移动。

- `TextEdit` 保存最后提交的字号、字重、可用内容宽度、视口高度和 `TextEngine` 引用；新增 `configureLayout(...)`、`ensureLayout()`。
- `ensureLayout()` 用当前 `display()`（含组字）和上述参数取得缓存布局。仅内容、字号、字重或宽度变化时更换布局；光标和选区变化不重新排版。
- 任何依赖行几何的按键、鼠标命中、IME 几何查询之前均调用它。不得通过重建视图、嵌套调用 `buildAndLayout` 或把原始按键留到下一帧来绕开这个问题。
- 尺寸变化以最近完成布局的宽度为准；新的 frame 布局完成后更新配置。事件期查询不写回池化 Node，不访问可能重用的节点下标。

### 2.4 文本框自己滚动，不包装一个子滚动容器

- 多行框设 `SCROLL | SCROLL_Y`，复用已有滚轮、惯性、滚动条、命中链。`ElementState.scrollY` 为唯一纵向偏移来源，不再增加独立的 `TextEdit.scrollY`。
- `FlexLayout.place` 对叶子 INPUT 会提前返回，因此它不会算滚动内容尺寸；不能照搬普通滚动容器的“子元素总高度”。
- 新增 `Engine.layoutInputs()`：在每次 `layout.layout(...)` 之后执行，计算输入框最终布局、`contentH`、偏移夹取、光标揭示、节点绘制坐标及事件期配置。普通 reveal 导致再次布局、列表第二轮布局也必须经过此入口。
- 布局前读取状态的 offset/request，布局后得出节点结果，最终 `commit()` 再写回；不得先在 `commit` 写入默认 `n.contentH=0` 或清掉请求，再计算多行框。
- 一帧内重布局时优先使用节点上最近算出的 offset/request，不反复从上一帧的 `ElementState` 读旧值；caret reveal 的本帧请求保留到最终 commit，再清除，所以列表第二轮或祖先 reveal 引起的布局仍能按最终宽度校正位置。
- 现有单行 `inputGeometry` 纳入相同的布局后阶段，但单行横向居中、横向光标揭示等行为不变。

## 三、公开 API 和行为决定

### 3.1 API

```java
Ui.textArea(Context context, TextRef value);
Ui.textAreaBase(Context context, TextRef value);
Element.lines(int min, int max);
```

- 返回 `Element`，可接 `.height(...)`、`.grow(...)`、`.padding(...)`、`.placeholder(...)`、`.readOnly(...)`、`.onPaste(...)`、`.onTextKey(...)`、`.setTextSelection(...)`、`.inputMethod(...)`。
- `lines` 只适用于多行输入框；`min >= 1 && max >= min`。开发模式误用抛 `IllegalStateException`，非开发模式忽略无效调用。每帧默认未设置，不再调用就失效。
- Enter 和 Shift+Enter 插入 LF；`submitted()` 和 `onSubmit` 不因多行框的 Enter 触发。回车发送由 `onTextKey` 实现，返回 true 时不插入换行。
- Tab/Shift+Tab 移焦点，进入多行框时全选（同现有输入框/MyGO）；钩子取走 Tab 则不移焦点。

### 3.2 宽高和外观

- `textAreaBase` 没有背景、边框、padding、硬性最小高度；默认内容宽度 200 DIP，最小可收缩宽度为 0。
- `textArea` 使用现有输入框样式：padding 6/10、主题圆角、Surface 背景、1 DIP 边框，焦点/悬停边框颜色沿用 `textInput`，不画额外焦点环。
- 未设 `lines` 时，自然内容高度为 `max(硬段数, 3) × 基准行高`，基准行高沿用 `TextEngine.lineHeight(size, weight)`；软换行不让这个默认高度增长。
- 带样式框默认的自然外框高度至少 80 DIP。**80 是默认自然尺寸，不强制覆盖用户显式 height 或 lines**；显式 `height` 优先，`minHeight`/`maxHeight` 和父级 flex 约束照常生效。
- 设了 `lines(min,max)` 时，自然内容高度为 `clamp(实际换行高度, min × 基准行高, max × 基准行高)`，再加 padding/border。字体回退可能让某行更高，“行数”是基准行高预算，不保证恰好显示相同数量的回退字体行。
- 未聚焦时也保留纵向偏移；placeholder 在空文且没有组字时显示，顶对齐、按内容宽度换行，不参与真实文本高度和选区。
- 内容宽度为 0 或极小时，用有限正宽度下限（0.01 DIP）排版，保证每次断行至少前进一个完整字素簇，不能无限循环或拆开代理对。

### 3.3 硬换行和索引

- 所有公开选区、编辑、IME 下标仍是 UTF-16，不能落在代理对或组合字素内部。
- 空字符串也有一条空视觉行；`"a\n"` 有两行，`"\n\n"` 有三行。最后一条空行必须能放光标，具有正行高。
- 传入的 `TextRef` 不被控件静默重写；`\n`、`\r\n`、独立 `\r` 均可作为硬换行。CRLF 在源字符串中占两个 UTF-16 单位，是一个不可分开的换行字素。行表保留源下标，不通过去掉 CR 后的临时字符串向外返回错位下标。
- 用户提交/粘贴的文字在插入时把 CRLF 和独立 CR 统一为 LF；替换范围仍解释为修改前文档的 UTF-16 范围。应用直接设置的文字保持原样。
- marked text 按输入法原样保留（包括 CRLF），其 selectedRange 不先归一化；提交或 unmark 时再转成 LF，光标按实际插入长度定位。不能先清洗 marked text 再套用原来的选区下标。
- 单行框的换行转空格策略完全不变。

### 3.4 光标亲和性（affinity）

- 只在软换行边界，同一个下标可能指向上一行末尾或下一行开头。`TextEdit` 为 caret 和 anchor 各存 `upstream` 布尔值：true 为上一行末尾，false 为下一行开头。
- ←/→ 在软换行边缘保留两个视觉停点，跨边界需要先换亲和性再走到相邻字素（同 MyGO）；硬换行没有这种重复停点，跨 CRLF 作为一步。
- 点击视觉行末尾右侧：返回这一行的 end 和 upstream；点击下一行开头返回同一 index 的 downstream。
- Home/⌘← 到当前视觉行开头，End/⌘→ 到当前视觉行末尾，并保留该行亲和性。不能复现参考版本 End 后画在下一行开头、再 Home 跳到下一行的问题。
- `setTextSelection` 仍只接受下标，两端采用 downstream（段尾/文末没有歧义时自动归一）；不扩大已有 API。
- Undo/Redo 除原有文字、anchor/caret 外还恢复两端亲和性，避免在软换行处撤销后光标跳行。

### 3.5 键盘

| 按键 | 多行框行为 |
|---|---|
| Enter / Shift+Enter | 插入 LF，不提交表单 |
| ↑ / ↓，Ctrl+P / N | 按视觉行移动，保留连续纵向移动的目标 x；越过首/末行分别到文首/文末 |
| Shift+上述移动 | 只移动 caret，保持 anchor 和它的亲和性 |
| PageUp / PageDown | 移动 `max(1, floor(内容视口高度 / 基准行高) - 1)` 个视觉行，再最少滚动揭示 caret |
| Home / End，⌘← / ⌘→ | 当前视觉行首尾 |
| ⌘↑ / ⌘↓，Ctrl+Home / End | 文首/文末 |
| ⌥← / ⌥→ | 沿用现有按词移动，可以跨硬换行 |
| ⌥↑ / ⌥↓ | 与普通 ↑/↓ 一样，参考版本没有按段移动 |
| Backspace / Delete | 前/后字素删除，可删换行连接两段；⌥ 按词删除 |
| ⌘Backspace | 删到当前视觉行首；若已在行首，不额外删除前一段 |
| Ctrl+A / E | 当前硬段首尾，不是软换行首尾 |
| Ctrl+K | 删到硬段尾；恰在段尾且还有下一段时删换行并连接两段 |
| Ctrl+B / F / H / D | 同 ← / → / Backspace / Delete |
| Tab / Shift+Tab | 移焦点；不插入制表符 |

- 上下移动从活动端出发，不先折叠选区；横向无 Shift 移动先折叠到相应端。
- 水平移动、鼠标、编辑、外部值替换、显式设置选区清除目标 x；纯上下/翻页移动保留它，经过短行后再到长行能回到原来的列。
- `TextEdit.wants` 的模式判断在普通按键处理和 `onTextKey` 的优先级判断里使用同一入口，不得只改其中一处。
- 只读时仍只接受复制/全选和带 Shift 的选择移动；普通 ↓、空格、翻页交给滚动，多行框自己先滚，到边缘再交给外层。沿用计划一的菜单命令和快捷键规则。

### 3.6 鼠标和绘制

- 点击使用 `(x - 文本原点x, y - 文本原点y)` 二维命中；上方取第一行，下方空白取最后一行中最接近 x 的位置，行尾右侧取该行末尾。
- Shift+点击扩展；双击选词，双击后拖动按词扩展且不跨行吞掉换行；三击选当前视觉行，不包括硬换行，三击后的拖动不扩展（同 MyGO）。
- 先提交组字再点击定位时，必须按新布局重新命中，不能把组字期间的行表沿用到提交之后。
- 拖出框外：每次移动把 caret 放到相应的离屏行，布局阶段揭示它；不另起持续 autoscroll 定时器。
- 绘制顺序：背景、逐行选区、文字、逐行组字下划线、光标、边框、滚动条。保持 INPUT 现有 border 内侧矩形裁剪；不借本计划改变它的圆角裁剪策略。
- 跨软换行的选区仅覆盖该行文字（含尾部空格）；选中硬换行，在该段末行画 `fontSize/3` 宽的可见短块；空行也有短块。结束位置恰在下一段开头时不多画下一段。
- caret 为当前视觉行的完整高度，宽度、颜色、530 ms 闪烁/30 s 后常亮沿用现有实现；只读/禁用不画。
- 新增 `Scene.text(layout, x, y, color, firstLine, endLine)`，行范围左闭右开；复用已有字形写入，不为每行建临时数组，也不为离屏行访问 atlas。原来的整段重载保留。

### 3.7 滚动与光标揭示

- 内容外框高度 `contentH = 实际文本高度 + 上下padding + 2×border`，偏移夹到 `[0, max(0, contentH - h)]`；横向 offset 恒为 0，长词强制断行，不提供 noWrap。
- 新编辑器的 caret 在文末，首次布局带一次 reveal，所以长初始值会显示末尾（同 MyGO）。
- 编辑、方向键/翻页、鼠标、组字、Undo/Redo、`setTextSelection` 请求揭示；鼠标滚轮、滚动条、单纯闪烁和失焦不请求。应用直接改 `TextRef` 时只夹取 offset，不强行拉回 caret。
- reveal 将 caret 放进 padding 内的内容视口，按最小距离滚动。文字绘制仍可穿过 padding，最终裁剪在 border 内侧。
- reveal 请求在最终几何阶段消费；若内容改变、宽度改变导致重排，再以最终布局校正一次。之后只有闪烁的帧不得再次拉回。
- caret reveal 停止该框的滚轮 glide，即使当前已能看到光标、无需移动 offset，也不能让后续惯性把 caret 带走；用户滚轮/拖条则接管位置，不被残留 reveal 持续覆盖。
- 已有 `Element.scrollIntoView()`/Tab 揭示的是整个控件在祖先容器中的位置；内部 reveal 只负责自己的 caret，两者互不替代。

### 3.8 输入法、钩子和撤销

- `MacWindow.Input`、`Window` 的 UTF-16 范围和屏幕坐标转换接口原则上不变；多行几何在 Engine 内实现，不新增另一组 NSTextInputClient 方法。
- `textIndexAt(x,y)` 使用二维查询；`textCaretRect` 返回真实 caret 所在行；`Input.updateTextInput` 比较 caret 的 x、y、height，换行或滚动后必须通知候选框更新。
- 空范围返回对应插入点的 1 DIP 宽矩形；非空范围返回首个字素的矩形，不合并跨行的大矩形。沿用 `out[4]` 为实际覆盖范围的源 UTF-16 end，并允许 `out[5]` 返回 actualStart：原生请求可能落在 emoji/CRLF 中间，不能只改结束位置。
- `MacWindow` 的复用 `rectOut` 扩为6项，调用前将 actualStart 初始化成请求的 start，兼容现有回调；多行实现填写校正后的两端，`firstRect` 用实际两端写回 NSRange。不改 NSTextInputClient 方法签名，也不扩展公共选区单位。
- 延续 j-ui 的候选框策略：查询落到视口外时把矩形夹在 border 内，仍返回实际字符下标；不改为 MyGO 的零矩形。
- marked text 合入 display 参与换行，每个可见视觉行都有下划线；仍不写进 `TextRef`，选词提交/取消/unmark 沿用 M4 语义。取消不是“空字符串提交”。
- 组字时变只读/禁用丢弃，关闭输入法提交；无重复插入、无重复 discard，提交的文字 `changed()` 恰好报告一次。
- `onPaste`、`onTextKey`、Edit 菜单共用计划一规则。普通 Enter 插入 LF；钩子取走 Enter 可发送，Shift+Enter 放行可换行。`TextKey.setText` 按多行模式保留 LF。
- 普通换行可以加入一秒内的连续打字撤销步骤；Paste/Cut/Delete 菜单命令、按词/行删除、一次组字各是独立步骤。新多行粘贴即使只有一个字符也不与前面的打字合并。单行已有撤销测试不得放宽。
- 外部值同步继续沿用 j-ui 规则：在用户编辑被写回的同帧，应用的格式化修改并入该步；无关的外部替换清空历史。不会为模仿 MyGO 改掉计划一这条约定。

`TextLayout` 的无分配查询接口：

```java
int lineStart(int line);
int lineEnd(int line);             // 不包括硬换行字符
int lineBreakEnd(int line);        // 下一段开始；软换行时等于 lineEnd
float lineTop(int line);
float lineHeight(int line);
float lineWidth(int line);
int lineAt(int index, boolean upstream);
int lineForY(float y);
float caretX(int index, boolean upstream);
void hitTest(float x, float y, int[] out); // out = {UTF-16 index, upstream ? 1 : 0}
boolean selectionRect(int start, int end, int line, float[] out); // out = {x,y,w,h}
```

- `lines` 仍是行数，行数组不直接对外暴露。旧 `caretX(index)`、`indexAt(x)` 保留兼容现有单行路径。
- `hitTest`、`selectionRect` 的 out 由编辑器/绘制器预先持有并复用，不在 steady frame 新建 record、Rect、Stream 或回调。
- line glyph 范围提供内部只读 getter 给 `Scene`；不在两个包间复制布局。
- 字形baseline继续保存在已有glyph坐标数组，不额外复制到行表；空行只需要正行高，不保留原生CTLine。
- 全部依赖几何的调用先 `ensureLayout()`；用 `lineTop(lineAt(...))`、`lineHeight(...)` 组合光标 y/h，不引入分配对象。

## 七、Review Focus 与回归样例

整体审查必须逐项说明结果，不用“测试都通过”代替：

1. **事件间布局是否新鲜**：新LF、paste、onTextKey.setText、IME变更后不跑帧，紧接上下移动和原生几何查询。
2. **软换行亲和性**：同下标两个视觉位置，点击行尾、End→Home、上下目标x、撤销恢复，不能跳错行或进代理对。
3. **换行索引**：空文、首/末空行、连续LF、CRLF、独立CR、emoji/CJK/组合字符；实际范围必须是源UTF-16。
4. **滚动与揭示争用**：首次在末尾、wheel离开后blink不拉回；方向键再揭示；glide/滚动条接管；嵌套scroll和列表第二轮不重复消费。
5. **计划一行为不退化**：事件前后只读/禁用/IME切换、onPaste取走、onTextKey发送清空、TextRef与changed恰好一次；单行横向滚动和密码显示不受新布局影响。
6. **性能不是仅靠scissor**：Scene不能给所有离屏行发射字形或访问图集；热查询不能创建数组/Rect；缓存和原生对象所有权有界。

## 八、与参考版本的明确差异

| 项目 | 本计划 | MyGO `8049993` |
|---|---|---|
| 存储与布局 | String整文缓存，复用硬段排版但即时测量全部段落，画可见行；普通表单/短备注 | 按段缓存、估高、虚拟布局，可处理更长内容 |
| UTF-16 | 延续j-ui所有编辑/选区下标约定 | 公开设置选区按码点；原生client用UTF-16 |
| Home/End affinity | 留在当前视觉行的实际首尾 | 部分路径转为downstream而画在下一行 |
| 主题80高度 | 仅默认自然尺寸下限，显式height/lines可以更小 | styled控件的MinHeight80也会限制Lines |
| PageUp/Down | 用内容视口高度估算页 | 参考实现用元素外框高度 |
| 独立CR插入 | 用户插入统一LF；外部原文和marked text仍保留源下标 | 主要只归一化CRLF，独立CR保留 |
| 离屏IME矩形 | 保留j-ui现有夹到边缘的策略 | 返回不可见/零矩形 |
| 外部值的撤销 | 只在回应同帧用户编辑时合入撤销 | 更广泛把应用改写折入上一步 |

其余上述按键、Tab、默认高度随硬段数增长、初始文末、词选择、三击视觉行、无定时拖选autoscroll均以参考版本为依据，不改成未说明的AppKit默认。
